# Feature Specification: 首次部署初始化引导

**Feature Branch**: `feat/keycloak-sso`

**Created**: 2026-10-15

**Status**: Draft

**Input**: 在 ECS 上运行一个交互式脚本，引导运维人员输入名称和账号，一次完成平台初始化：Keycloak 管理员账号、Paperclip 公司、Paperclip 管理员账号，并把公司关联到 Keycloak 组织、关闭邮箱注册、重新部署生效。可重复执行，已完成的步骤跳过。员工日常管理不在范围内，统一在 Keycloak 管理台操作。

**Related**: [001](../001-keycloak-sso-aliyun/spec.md)（首个管理员与组织映射的手动流程）

## Clarifications

### Session 2026-10-15

- Q: Keycloak 管理员账号的权限范围？ → A: 全局管理员（master realm 的 admin），与 `provisioner` 相同；当前只有一个 realm。
- Q: Paperclip 管理员用什么方式登录？ → A: 两种都可以：邮箱密码（应急）和企业账号；脚本在组织中建一个同邮箱的 Keycloak 账号，企业登录后自动关联为同一个 owner。
- Q: 管理员的企业账号密码和应急密码是否相同？ → A: 分开设置，分别输入，不允许相同。

## 现状与要改的部分

首次部署后，运维人员现在要手动完成：在服务器上生成邀请链接 → 浏览器里注册应急管理员并接受邀请 → 在网页引导里建公司 → 查公司 ID → 编辑服务器上的配置文件 → 重新部署；Keycloak 管理台只能用部署自带的 `provisioner` 账号。步骤多、容易出错，网页引导还会强制要求先配置 agent。

本功能用一个在服务器上运行的引导脚本替代这些步骤。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一次完成首次初始化 (Priority: P1)

运维人员在刚部署好的服务器上运行引导脚本，按提示输入信息，结束后员工即可用企业账号登录进入公司。

**Independent Test**: 在全新部署上运行脚本并按提示输入，结束后用 Keycloak 中的组织成员账号企业登录，直接进入新建的公司；用输入的 Paperclip 管理员账号密码登录，或用其同邮箱的企业账号登录，都是实例管理员和公司 owner；用输入的 Keycloak 管理员账号能登录 Keycloak 管理台。

**Acceptance Scenarios**:

1. **Given** 刚完成首次部署、还没有管理员和公司，**When** 运行脚本并依次输入 Keycloak 管理员（用户名、密码）、公司名称、Paperclip 管理员（姓名、邮箱、应急密码、企业账号密码），**Then** 三者以及管理员同邮箱的企业账号都被创建，公司与 Keycloak 组织完成关联，邮箱注册被关闭，平台重新部署并通过健康检查。
2. **Given** 同上，**When** 脚本结束，**Then** 屏幕上给出下一步说明：管理台地址、在 Keycloak 中如何添加员工，且不显示任何密码。
3. **Given** 运行中途输入了确认"否"，**When** 脚本退出，**Then** 不做任何改动。

### User Story 2 - 重复执行与已有数据 (Priority: P2)

脚本可安全地再次运行，例如中途失败后重试，或像当前生产环境那样已经手动完成了一部分。

**Acceptance Scenarios**:

1. **Given** 已有 Paperclip 管理员和公司（例如此前通过网页引导创建），**When** 运行脚本，**Then** 显示已有的管理员和公司，不再要求创建，让运维人员选择要关联的公司，并完成其余步骤。
2. **Given** Keycloak 管理员账号已存在，**When** 运行脚本，**Then** 跳过该步骤，不修改其密码。
3. **Given** 公司已关联且邮箱注册已关闭，**When** 运行脚本，**Then** 报告"已完成"，不重新部署。
4. **Given** 某一步失败（例如平台未运行），**When** 脚本退出，**Then** 给出失败原因，已完成的步骤保留；修复后重新运行可从失败处继续。

### Edge Cases

- 密码两次输入不一致、不满足强度要求，或企业账号密码与应急密码相同：提示后重新输入。
- 输入的 Paperclip 管理员邮箱已被占用：提示并让运维人员换一个邮箱重新输入。
- 有多家公司：列出并让运维人员选择要关联的那一家。
- 平台或 Keycloak 未运行：直接报错退出，不做任何改动。

## Requirements *(mandatory)*

- **FR-001**: 脚本在 ECS 上以 root 运行，交互式提示输入，所有密码输入不回显，且不出现在屏幕输出、日志和命令历史中。
- **FR-002**: 创建一个 Keycloak 全局管理员账号（master realm 的管理员，权限与 `provisioner` 相同），用于日常管理；部署自带的 `provisioner` 账号保留不动。
- **FR-003**: 创建 Paperclip 公司，名称由运维人员输入。
- **FR-004**: 创建 Paperclip 管理员账号（邮箱 + 密码登录），使其成为实例管理员和该公司的 owner。该账号即应急管理员，在 Keycloak 不可用时仍可登录。
- **FR-004a**: 在 Keycloak 组织中创建一个与 Paperclip 管理员同邮箱、邮箱已验证的员工账号，使管理员也能用企业账号登录，登录后即为同一个 owner 账号。该企业账号的密码单独输入，且必须与应急密码不同。
- **FR-005**: 把公司关联到部署配置中的 Keycloak 组织，关闭邮箱注册，并重新部署当前版本使之生效。
- **FR-006**: 每一步执行前检查是否已完成，已完成则跳过并说明；整个脚本可重复执行。
- **FR-007**: 执行任何改动前汇总将要做的事并请运维人员确认。
- **FR-008**: 不涉及员工管理：除 FR-004a 的管理员本人账号外，不创建员工、不修改组织成员、不分配角色。

## Success Criteria *(mandatory)*

- **SC-001**: 运维人员在首次部署后 10 分钟内完成初始化，无需打开浏览器、无需手动编辑配置文件。
- **SC-002**: 初始化完成后，Keycloak 组织成员首次企业登录即进入公司。
- **SC-003**: 重复运行脚本不产生重复的账号或公司，也不改动已有账号的密码。

## Assumptions

- 平台已通过 001 的流程完成首次部署，服务正在运行。
- 一个部署只对应一个 Keycloak 组织和一家关联公司。
- 以后如需由 Keycloak 角色决定谁是 Paperclip 管理员，另行立项。
- 网页引导中"连接模型/创建 agent"不在本功能内，可在 Agents 页面随时创建。
