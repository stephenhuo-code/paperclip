# Feature Specification: 管理员计价与按计价执行预算

**Feature Branch**: `feat/keycloak-sso`

**Created**: 2026-10-17

**Status**: 已被 006 替代（不实施）

**Input**: 1) 运行工具自己上报的费用（及 Paperclip 内置价格）保持不变，作为"成本"展示；2) 管理员（owner/admin）可以为每个模型设置计价单价（输入、缓存命中、缓存写入、输出，每百万 token），系统提供默认值（常用模型的默认单价和一个兜底默认单价），管理员可修改；每次运行按管理员设置的计价算出"计价金额"，预算（现有的公司 / agent / 项目预算）以计价金额为准执行。不改预算模型本身（范围、周期、超额处理保持现状）。

## Clarifications

### Session 2026-10-17

- Q: 订阅方式的运行是否也按管理员单价计价并计入预算？ → A: 是，所有运行一律按单价计价。
- Q: 历史运行是否补算计价金额？ → A: 不补算，只计价上线后结束的运行；历史运行计价金额为空，不计入预算。
- Q: 单价与计价金额用什么币种？ → A: 美元，沿用现有金额显示与预算输入。

## 现状与要改的部分

现在每次运行的费用只有一个数：运行工具自己上报的金额，或少数模型（Claude Sonnet 5、5 个 GPT 模型）的内置价格；其余记为"未定价"。订阅方式的运行一律记 0。价格不能配置。预算按这个数执行，结果是：

- DeepSeek、MiniMax 等通过自定义网关接入的运行被当成订阅，记 0，不占预算；
- Kimi 会员等订阅运行记 0，永远不会触发预算；
- 有"未定价"记录的范围一旦设置预算，会被直接暂停。

本功能增加第二个数——**计价金额**，由管理员设置的单价决定，预算改为按计价金额执行；原来的数改称**成本**，保持不变。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员设置模型单价 (Priority: P1)

公司 owner/admin 打开计价设置，看到系统预置的常用模型默认单价和一个兜底默认单价，可以修改任何一项，也可以为新模型添加单价。

**Independent Test**: 以 admin 登录，打开计价设置，看到默认单价列表；把 `deepseek-chat` 的输出单价改为新值并保存，刷新后仍是新值；以普通员工登录，只能查看、不能修改。

**Acceptance Scenarios**:

1. **Given** 公司从未设置过计价，**When** admin 打开计价设置，**Then** 看到常用模型（Claude、GPT、DeepSeek、Kimi、MiniMax 系列）的默认单价和兜底默认单价，每项都标明"默认值"。
2. **Given** 同上，**When** admin 修改某个模型的单价并保存，**Then** 该模型显示为"已自定义"，之后的运行按新单价计价。
3. **Given** admin 添加一个默认列表中没有的模型及其单价，**When** 该模型产生运行，**Then** 按新添加的单价计价。
4. **Given** admin 把某个已自定义的模型"恢复默认"，**When** 之后产生运行，**Then** 按默认单价计价。
5. **Given** 普通员工，**When** 打开计价设置，**Then** 只能查看单价，不能修改。

### User Story 2 - 每次运行同时有成本和计价金额 (Priority: P1)

每次运行结束后，系统照旧记录成本，同时按管理员单价算出计价金额。费用页同时展示两者。

**Independent Test**: 用一个 DeepSeek agent 跑一次任务，费用页该 agent 的计价金额 = 各类 token 数 × 对应单价之和；成本仍按原规则显示（此例为 0）；用一个 Claude 直连 agent 跑一次，成本是工具上报值，计价金额按管理员单价计算，两者可能不同。

**Acceptance Scenarios**:

1. **Given** 模型有单价（自定义或默认），**When** 运行结束，**Then** 计价金额 = 普通输入 × 输入单价 + 缓存写入 × 缓存写入单价 + 缓存命中 × 缓存命中单价 + 输出 × 输出单价（按每百万 token 折算）。
2. **Given** 模型既没有自定义单价也不在默认列表中，**When** 运行结束，**Then** 按兜底默认单价计价，并在费用页标出"按兜底单价计价"的模型及用量，提示管理员补充单价。
3. **Given** 任意运行，**When** 计价，**Then** 成本（工具上报值、内置价格或未定价）保持现在的规则不变。
4. **Given** 费用页，**When** 查看按公司、agent、项目、模型的汇总，**Then** 计价金额与成本分别显示，计价金额为主。
5. **Given** 管理员修改了单价，**When** 查看修改前已结束的运行，**Then** 其计价金额不变，且能看出当时使用的单价。
6. **Given** 订阅方式的运行（如 Kimi 会员、Claude 订阅），**When** 计价，**Then** 与按量运行一样按单价算出计价金额并计入预算；成本仍为 0。

### User Story 3 - 预算按计价金额执行 (Priority: P1)

现有的公司 / agent / 项目预算改为按计价金额统计和触发，范围、周期、预警和超额暂停的行为不变。

**Independent Test**: 给 DeepSeek agent 设月度预算 1 美元，让它运行到计价金额超过 1 美元，agent 被暂停并生成超预算申请；成本始终为 0。

**Acceptance Scenarios**:

1. **Given** agent 设有月度预算，**When** 其本月计价金额达到预警比例 / 上限，**Then** 分别发出预警 / 暂停该 agent，与现在按成本执行时的行为一致。
2. **Given** 项目或公司预算，**When** 计价金额达到上限，**Then** 按现有规则暂停项目或公司。
3. **Given** 有兜底单价的存在，**When** 设置预算，**Then** 不会因为"未定价"而直接暂停（所有运行都有计价金额）。
4. **Given** 预算页面，**When** 查看已用额度，**Then** 显示的是计价金额。

### Edge Cases

- 单价为 0：允许（例如免费模型），计价金额为 0。
- 单价输入非数字或为负：拒绝保存并提示。
- 缓存写入单价不填：按输入单价计算。
- 一次运行使用多个模型：按每个模型各自的单价分别计价后相加；无法区分时按兜底单价计价并标记。
- 运行工具没有报告 token 数：计价金额为 0 并标记"无用量数据"。
- 不按 token 计费的费用（如浏览器服务等按次收费的记录）：计价金额等于成本。
- 模型名大小写或别名不同：按完全一致的模型名匹配；不匹配的走兜底单价，在费用页可见。
- 同一时刻修改单价与运行结束：以运行结束时生效的单价为准。

## Requirements *(mandatory)*

- **FR-001**: 每家公司有一张计价单价表，按模型名区分；每个模型有输入、缓存命中、缓存写入（可选）、输出四个单价，单位为每百万 token。
- **FR-002**: 系统提供常用模型的默认单价和一个兜底默认单价；公司未自定义时使用默认值。
- **FR-003**: owner/admin 可以修改、添加、恢复默认任何单价，包括兜底单价；其他成员只能查看。每次修改记录在活动日志中（谁、何时、旧值、新值）。
- **FR-004**: 每次运行结束时按当时生效的单价算出计价金额，并记录所用单价及其来源（自定义 / 默认 / 兜底），之后修改单价不影响已记录的金额。
- **FR-005**: 成本的记录规则保持不变（工具上报值优先，其次内置价格，否则未定价；订阅记 0）。
- **FR-006**: 费用页同时展示计价金额和成本，计价金额为主；列出按兜底单价计价的模型及用量。
- **FR-007**: 现有预算（公司 / agent / 项目，月度 / 累计，预警、硬上限、暂停、超额审批、自动恢复）改为按计价金额统计和触发，其余行为不变。
- **FR-008**: 只对上线后结束的运行计价；上线前的运行计价金额为空，不计入预算，费用页对其只显示成本。
- **FR-009**: 单价与计价金额使用美元，与现有金额显示和预算输入一致。

## Key Entities

- **计价单价**：公司、模型名、四个单价、来源（默认 / 自定义）、生效时间、修改人。
- **运行计价记录**：运行、模型、各类 token 数、计价金额、所用单价及来源；与现有成本记录并存。

## Success Criteria *(mandatory)*

- **SC-001**: 上线后，100% 的有 token 用量的运行都有计价金额（无"未定价"），预算不会因缺价格而误暂停。
- **SC-002**: admin 能在 2 分钟内修改一个模型的单价，修改后的下一次运行即按新单价计价。
- **SC-003**: 对任意一次运行，计价金额可由页面显示的 token 数和单价手工复算，误差不超过 1 美分。
- **SC-004**: 设置预算后，DeepSeek / MiniMax / Kimi 等 agent 的用量能触发预警和暂停。
- **SC-005**: 成本相关的现有显示与统计结果在上线前后保持一致。

## Assumptions

- "管理员"指公司的 owner / admin；实例管理员（instance admin）也可修改。
- 单价表按公司各自维护；新公司从默认值开始。
- 默认单价参考各服务商公开的标准价格，在上线时确定一次，之后随版本更新；已自定义的单价不会被版本更新覆盖。
- 不支持按上下文长度分档、按时段折扣、批量折扣等复杂定价。
- 预算的范围（公司 / agent / 项目）、周期、超额处理不变；按单个任务设预算不在范围内。
- 财务记录（账单导入、服务商费用报告）不受影响，仍单独显示。
